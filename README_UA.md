# My Tray — сайт (MVP)

Статичний адаптивний сайт + каталог модулів у `catalog.json`. Не використовує серверну БД, рекламні SDK чи аналітику. Демонстраційні модулі не додані; завантаження програми не вигадане.

## Файли
- `index.html` — сторінки/секції сайту.
- `style.css` — адаптивний дизайн.
- `app.js` — рендер каталогу, пошук, фільтри, деталі.
- `catalog.json` — контент, метадані релізу та модулів; цей файл є JSON manifest для My Tray.

## Рекомендоване безкоштовне розміщення: GitHub Pages
Підходить для статичного MVP. Вміст адмініструється редагуванням `catalog.json` через вебінтерфейс GitHub. Важливо: GitHub Pages публікує вміст репозиторію — не зберігайте там приватні файли, ключі чи адмінсекрети. Залежність від Google Fonts у CSS можна прибрати (локальні системні шрифти) для повністю автономного сайту.

### Публікація
1. Увійдіть або створіть обліковий запис GitHub (не рекомендовано створювати доступи через сторонніх посередників).
2. Створіть репозиторій, наприклад `my-tray-site`. Для GitHub Pages free зазвичай потрібен public repo.
3. Завантажте всі файли цього пакета у корінь репозиторію (`index.html`, `style.css`, `app.js`, `catalog.json`, `README_UA.md`).
4. У репозиторії: **Settings → Pages**. У Source оберіть **Deploy from a branch**, branch `main`, folder `/ (root)`, Save.
5. Дочекайтеся завершення deployment; перевірте URL виду `https://USERNAME.github.io/my-tray-site/`.
6. Для домену `360.pp.ua`: у Settings → Pages → Custom domain вкажіть `360.pp.ua` або бажаний піддомен. Після DNS-змін увімкніть HTTPS (Enforce HTTPS), коли опція стане доступна.
7. У DNS-панелі домену налаштуйте записи згідно актуальної офіційної інструкції GitHub Pages для apex-домену або CNAME для піддомену. Не змінюйте записи, які використовуються іншими службами, без резервного копіювання їх значень. DNS може поширюватися не миттєво.

### Додавання / оновлення модуля
1. Відкрийте `catalog.json` у репозиторії (кнопка Edit).
2. У `categories` додайте категорію, якщо потрібна.
3. У `modules` додайте об'єкт, дотримуючись схеми нижче. Перевірте URL, файл, hash та сумісність перед публікацією.
4. Commit changes. Сайт автоматично оновиться після deploy.
5. Архівуйте модуль, встановивши `status` у `archived`; приховуйте, встановивши `hidden`. Для публічного модуля використовуйте `available`, `new` або `updated`.

### Формат каталогу (catalog_version=1)
```json
{
  "id": "example-module",
  "name": "Назва",
  "icon": "◈",
  "category": "Інші",
  "short_description": "Короткий опис",
  "description": "Повний опис",
  "version": "1.0.0",
  "release_date": "2026-01-01",
  "size": "1 MB",
  "compatibility": "My Tray core >= 1.0",
  "download_url": "https://example.org/module.zip",
  "sha256": "...",
  "preview": "https://example.org/preview.png",
  "license": "...",
  "author": "...",
  "status": "available"
}
```
Всі наведені URL у прикладі — placeholders; замініть на перевірені адреси. Не додавайте фіктивні дані до реального каталогу.

### Підключення каталогу в My Tray
My Tray може завантажити JSON з URL `https://360.pp.ua/catalog.json` (або URL Pages на етапі тесту). Читати `catalog_version`; підтримувати поля modules/application/categories. Після завантаження пакета перевірити SHA-256 перед встановленням. Для production варто додати цифровий підпис каталогу/пакетів. У разі помилки мережі показати локально кешований каталог, не блокувати вже встановлені модулі.

### Завантаження основного застосунку
Заповніть поля `application` у `catalog.json`: version, release_date, download_url, size, system_requirements, sha256, release_notes. Перевірте файл і URL вручну перед commit. Поки URL порожній, кнопка навмисно неактивна.

### Резервна копія та відновлення
- Основна резервна копія: локальний clone або zip репозиторію; регулярно завантажуйте копію.
- Зберігайте копії release-пакетів і hash окремо.
- Відновлення: створіть репозиторій з копії файлів або відновіть потрібний commit через GitHub history.
- Git history є версіонуванням, але не замінює незалежну резервну копію.

### Перед запуском
- Перевірити на мобільному і desktop, пошук, фільтр, modal, URL та файли.
- Перевірити JSON синтаксис (не допускайте trailing comma).
- Не вважайте сайт опублікованим на `360.pp.ua` до реального DNS/HTTPS тесту.
- Налаштування DNS та публікацію на домені не виконано автоматично; потрібні власник домену й доступ до GitHub/DNS.

## Обмеження MVP
- Не реалізовано серверний CMS/admin login: редагування через GitHub, обліковий запис захищайте 2FA.
- GitHub Pages — статичний хостинг, немає server-side API чи backend-автентифікації.
- Для великих файлів релізи/файлове сховище варто розміщувати окремо, перевіривши квоти/умови.
- Не виконано зовнішніх тестів, перевірки DNS/SSL, завантажень або конкретних модулів — оскільки реальних даних/файлів не надано.
